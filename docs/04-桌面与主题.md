# 04 · 桌面与主题

桌面用的是开源项目 [CleanYourTV](https://github.com/Gathin23/cleanyourtv) 的启动器：
纯 Java、约 572 KB、无网络权限、Apple TV 那种"玻璃底板 + 大标题"的风格。

## 一个关键细节：改包名

这台电视上它不叫 `com.gathin.tvhome`，而是被改成了 **`com.coocaa.tvhome`**，
Activity 类名仍然是 `com.gathin.tvhome.MainActivity`（清单里 `package` 改了，`android:name` 没改）。

原因：创维的固件对 Home 有额外的判断，伪装成自家的包名能少踩坑。副作用是
`run-as` 进不去（非调试包），改配置只能走下面的 provider。

## 配置从哪来

桌面从自己的**外部 files 目录**读两个文件：

```
/sdcard/Android/data/<桌面包名>/files/config.json
/sdcard/Android/data/<桌面包名>/files/wallpaper.jpg
```

`config.json` 是**整体覆盖**，不是合并：推上去的键替换掉上一份，没写的键回落到 APK 内置的
`config.xml`。所以改之前一定要先读回当前配置。

## 写入通道：ThemeProvider

shell 被挡在 `Android/data` 外面（实测 `mkdir` 就是 Permission denied），所以走桌面自带的
ContentProvider：

```bash
adb push config.json /data/local/tmp/cyt-config.json
adb shell "content write --uri content://com.coocaa.tvhome.theme/config.json < /data/local/tmp/cyt-config.json"
adb shell "content read  --uri content://com.coocaa.tvhome.theme/config.json"
```

`config read` 能读回来，所以「读-改-写」是安全的。

**注意 provider 的权限**：清单里是

```xml
<provider android:name="com.gathin.tvhome.ThemeProvider"
          android:authorities="com.coocaa.tvhome.theme"
          android:permission="android.permission.WRITE_SECURE_SETTINGS"
          android:exported="true" />
```

也就是说**普通 App 写不进去**，只有 shell（有 WRITE_SECURE_SETTINGS）或拿到该权限的应用才行。
自己的 App 想写，得装好后 `pm grant <包名> android.permission.WRITE_SECURE_SETTINGS`。

## 有用的配置键（实测于该版本）

| 键 | 作用 |
|---|---|
| `dock_apps` | 玻璃条那排，**实测只吃 4 个**，多给的被忽略 |
| `greeting_name` | 时钟上方的问候语后面那个名字 |
| `show_inputs_pill` | 顶部"输入源"按钮 |
| `coocaa_sources` | **酷开专属**：信号源列表从 `com.skyworth.tv` 取。这台机器 `TvInputManager` 是空的，不开这个输入源按钮会消失 |
| `wallpaper` / `wallpaper_dim` / `wallpaper_true_color` | 壁纸开关、暗色蒙版、32 位色 |
| `ambient_glow` | 聚焦应用的颜色光晕。配照片壁纸时关掉，否则糊成一片 |
| `hidden_apps` | 从桌面上藏掉 App（App 还在，只是不显示） |

## 踩过的坑

1. **推一个键把整份配置冲掉**：只推 `background_color`，结果问候语、dock、输入源按钮全没了。
   → 永远先 `content read`，改完再写回。
2. **桌面只在启动时读配置**：改完必须让它重启（`am force-stop` + 重新启动 Home，
   或带 `FLAG_ACTIVITY_CLEAR_TASK` 启动它的 MainActivity），回前台不会重读。
3. **provider 会"假死"**：桌面进程活着，但 provider 查不到，连 shell 都读不了
   （`Could not find provider`），重启桌面进程才恢复。写这类工具时要有重试和失败提示。
