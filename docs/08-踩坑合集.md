# 08 · 踩坑合集

按踩到的顺序记录，每条都带现象和结论。

## 1. 按 Home 键回到的是固件桌面，不是 Android 桌面

见 [02](02-为什么Home键不听Android的.md)。结论：固件按 `persist.service.homepage.*` 直启组件。

## 2. 属性每次开机被改回去

`model.*` 被清空，`homepage.*` 被写回影视主页。结论：需要[守卫应用](03-固件守卫.md)反复重写。

## 3. 禁用影视主页之后，Home 键直接失效

以为禁用后会回落到默认桌面，实际是**什么都不发生**（焦点不动）。

结论：不要禁用固件指向的那个包，除非已经确保属性指向别处并且有守卫兜底。

## 4. 装完应用 `stopped=true`，开机广播永远收不到

守卫应用因此躺了八天没跑。结论：装完立刻启动一次它的组件清除停止态。

## 5. 改桌面配置只推一个键，把整份主题冲掉了

`config.json` 是**覆盖**语义。结论：先 `content read` 读回，改完再写。

## 6. 桌面 provider 会"假死"

进程活着，但 `content read` 报 `Could not find provider`，第三方 App 更读不到。
重启桌面进程才恢复。

结论：写工具时必须有重试和明确失败提示，别假定 provider 一定在。

## 7. 遥控器按一下音量，音量一路加到 100

不是硬件问题，是**某个无障碍服务拦了按键**却没把"抬起"送回来：

```
Bound services: Service[label=..., capabilities=9, ...]
capabilities=9 = CAN_RETRIEVE_WINDOW_CONTENT | CAN_REQUEST_FILTER_KEY_EVENTS
```

结论：有 `CAN_REQUEST_FILTER_KEY_EVENTS` 的无障碍服务在创维上会让音量键粘住。
清空 `enabled_accessibility_services` 后恢复正常。

## 8. 第三方悬浮窗被固件拒绝

想在桌面左上角画天气：

```
$ adb shell logcat | grep addView
sky_dialog: addView has denied!
```

`SYSTEM_ALERT_WINDOW` 和 `GET_USAGE_STATS` 都授了，窗口还是加不上。
结论：这台电视不允许任何应用往别人界面上盖东西，浮层方案全部不成立。

## 9. 桌面看不见 uid 1000 的应用

见 [06](06-投屏入口.md)。结论：用普通应用做壳。

## 10. `adb reboot` 用不了

```
$ adb shell reboot
/system/bin/reboot: inaccessible or not found
```

改用：

```powershell
adb shell svc power reboot
```

## 11. 装 APK 要过一道确认框

创维的 `com.coocaa.os.service/AdbInstallActivity` 会弹"正在通过 adb 安装此应用"，**6 秒倒计时**，
不按就自动取消并报 `INSTALL_FAILED_USER_RESTRICTED`。

自动化写法：后台发起 `adb install`，1.8 秒后按"右 → 确定"：

```powershell
$job = Start-Job { & adb -s $S install -r $apk }
Start-Sleep -Milliseconds 1800
adb shell "input keyevent KEYCODE_DPAD_RIGHT"
adb shell "input keyevent KEYCODE_DPAD_CENTER"
```

## 12. `WRITE_SECURE_SETTINGS` 不是 `pm grant` 就一定有

能 `pm grant` 是因为这个权限在清单里声明了、且 shell 有授予权。要在 App 里写桌面 provider，
必须先声明、再 `pm grant`，缺一步都是"能读不能写"。

## 13. 抓前台应用要靠 UsageStats

`ActivityManager.getRunningAppProcesses()` 在现代 Android 只返回自己。
判断"现在是不是在桌面"要用 `UsageStatsManager.queryEvents()`，并授 `GET_USAGE_STATS`。

（虽然最后因为浮窗被禁没用上。）
