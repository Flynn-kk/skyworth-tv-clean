# 03 · 固件守卫：让 Home 键永远指向我的桌面

[02](02-为什么Home键不听Android的.md) 的结论：固件每次开机都会把 `persist.service.homepage.*`
写回影视主页。所以要有个东西，开机后反复把它抢回来。

## 做法

一个 ~8 KB 的应用 `com.ccos.tv.homepage`，只有一个广播接收器：

| 触发 | 动作 |
|---|---|
| `BOOT_COMPLETED` / `LOCKED_BOOT_COMPLETED` | 立刻写属性，再排 2/8/20/45/90 秒各补一次 |
| 自定 action `com.ccos.tv.homepage.WATCH` | 只写属性（由 AlarmManager 每 10 分钟触发一次） |

```java
static void arm() {
    put("persist.service.homepage.pkg", LAUNCHER_PKG);
    put("persist.service.homepage.cls", LAUNCHER_CLS);
    put("persist.service.model.pkg",    LAUNCHER_PKG);
    put("persist.service.model.cls",    LAUNCHER_CLS);
}
```

写属性优先用 `android.os.SystemProperties.set()`（反射），失败再退到 `Runtime.exec("setprop …")`。
SELinux 是 Permissive，两种都能成功。

为什么要排好几个延时：固件改回属性发生在开机后的某个时刻（别的机型实测是 ~24 秒），
一次写不够，2/8/20/45/90 秒的窗口把这段盖住；之后每 10 分钟再兜一次底。

## 踩过的一个大坑：`stopped=true`

应用刚通过 `adb install` 装好时处于**停止状态**，`BOOT_COMPLETED` 广播**永远不会送到它**。

```
$ adb shell dumpsys package com.ccos.tv.homepage | grep 'User 0:'
User 0: ... stopped=true notLaunched=true     ← 开机广播不会来
```

这台机器上就发生过：守卫装好躺了八天，一次没跑过。

**解决**：装完立刻启动一次它的任意 Activity（或 `am start` 别的组件）清除停止态：

```powershell
adb shell am start -n com.ccos.tv.homepage/.LaunchActivity
# 之后再确认
adb shell "dumpsys package com.ccos.tv.homepage | grep 'User 0:'"   # stopped=false
```

## 验证它真的在工作

```powershell
# 1. 看日志
adb shell "logcat -d | grep CcHomeGuard"

# 2. 看闹钟有没有排上
adb shell "dumpsys alarm | grep ccos.tv.homepage"

# 3. 重启后按 Home 键，看焦点
adb shell input keyevent KEYCODE_HOME
adb shell "dumpsys window | grep mCurrentFocus"
```

## 怎么编译它

本机没有 Android SDK 也能编（见 `app/guard/build-guard.ps1`）：

1. JDK 17 + `android-30.jar` + `r8.jar`（脚本会自动下载）
2. `javac -source 8 -target 8 -bootclasspath android.jar`
3. `d8` 转 dex
4. **复用原 APK 的清单，只替换 `classes.dex`** —— 这样不需要 aapt 处理二进制清单
5. `jarsigner` 自签名（targetSdk 29，所以 v1 签名 Android 11 认）

第 4 步是这里最省事的技巧：拿任意一个已有的、清单里声明了 `BootReceiver` /
`LaunchActivity` / `Service` 的 APK 当壳，只换代码。
